IA como herramienta de desarrollo

Usar IA para programar no es hacer trampa — es una habilidad técnica más, con sus propias reglas. Acá vemos cómo generar, depurar, documentar y saber cuándo NO usarla.

📖 6 secciones ⏱ ~12 minutos de lectura 🐍 Ejemplos en Python
// En esta guía
1. IA para código 2. Copilot y asistentes 3. Depuración asistida 4. Documentación automática 5. IA + Python 6. Límites del asistente
01

IA para código

Ya sabés que una IA puede generar texto. También puede generar código — funciones, scripts completos, incluso proyectos enteros si el pedido es lo bastante detallado. Eso es útil, pero trae una trampa: es fácil pedir código que funciona sin entender por qué funciona.

Copiar y pegar un bloque de código que no podés explicar no es programar — es depender de una caja negra. La regla de esta sección es simple: si la IA te generó un código, tenés que poder explicarlo línea por línea antes de usarlo.

ejemplo — función generada por IA
def es_primo(n):
    # Un número primo solo es divisible por 1 y por sí mismo
    if n < 2:
        return False
    for i in range(2, int(n**0.5) + 1):
        if n % i == 0:
            return False
    return True

Antes de usar esta función en tu proyecto, deberías poder responder: ¿por qué el rango llega hasta la raíz cuadrada de n y no hasta n? ¿Qué pasa si n es negativo? Si no podés responder, todavía no es tuyo el código — es de la IA.

// Para recordar
Generar no es entender. Un código que no podés explicar es un riesgo, no una solución — sobre todo el día que falle y tengas que corregirlo vos solo.
02

Copilot y asistentes

No todas las herramientas de IA para programar funcionan igual. Conviene distinguir dos familias:

TipoCómo funcionaEjemplosMejor para
Autocompletado en el editor Sugiere código mientras escribís, directo en tu editor GitHub Copilot Completar patrones repetitivos, acelerar código que ya sabés escribir
Asistente conversacional Le explicás el problema en lenguaje natural y conversás Claude, ChatGPT Diseñar la lógica, depurar con explicaciones, aprender un concepto nuevo

La diferencia práctica: un autocompletado es rápido pero silencioso — no te explica nada, solo termina lo que empezaste. Un asistente conversacional es más lento, pero podés preguntarle "por qué" tantas veces como necesites. Para aprender, el segundo tipo suele ser más valioso.

03

Depuración asistida

Cuando un programa falla, hay dos formas muy distintas de pedirle ayuda a una IA — y solo una te deja algo aprendido.

código con error
numeros = [10, 20, 30]
for i in range(4):
    print(numeros[i])
# IndexError: list index out of range
✗ Pedido que no enseña nada "Arreglame este código."
✓ Pedido que enseña "Este código tira IndexError. ¿Por qué pasa, sin arreglarlo todavía — quiero entender la causa primero?"

El primer pedido te da una solución que podés copiar sin aprender nada. El segundo te obliga a entender el problema — en este caso, que range(4) genera índices 0 a 3, pero la lista solo tiene índices 0 a 2. Una vez que entendés la causa, arreglarlo es un paso trivial que además vas a recordar la próxima vez.

🐛
Regla práctica
Preguntá "por qué falla" antes de preguntar "cómo lo arreglo". El orden importa: entender la causa te sirve para el resto de tu carrera; una corrección copiada solo te sirve para esa línea.
04

Documentación automática

Las IA son buenas generando comentarios y docstrings rápido — pero "rápido" no es lo mismo que "correcto". Igual que con el código, la documentación generada hay que revisarla, no aceptarla de memoria.

docstring generado por IA — con un error
def calcular_descuento(precio, porcentaje):
    """
    Calcula el precio final sumando un descuento.

    Args:
        precio (float): precio original del producto
        porcentaje (float): porcentaje de descuento a aplicar

    Returns:
        float: precio final con el descuento sumado
    """
    return precio - (precio * porcentaje / 100)

¿Encontraste el error? El docstring dice "sumando" y "sumado" dos veces, pero la función resta el descuento — return precio - (...). Es un error típico de documentación generada: describe lo que "debería" hacer una función con ese nombre, no necesariamente lo que el código hace de verdad línea por línea.

// Para recordar
Revisá siempre que la documentación generada coincida con lo que el código realmente hace — no con lo que "suena razonable" que haga.
05

IA + Python

Python es el lenguaje puente de 2do curso, y es también donde más sentido tiene practicar todo lo anterior en conjunto. En un proyecto real — por ejemplo, uno de ICIENTEC — la IA puede acompañar distintas etapas, pero el criterio de cuándo y cómo usarla sigue siendo tuyo.

  • 01Planificación: pedirle a la IA que te ayude a pensar la estructura general del programa (qué funciones vas a necesitar) — vos decidís cuáles usar.
  • 02Primer borrador: generar una función puntual con la fórmula C-R-O-F, y explicarla antes de integrarla.
  • 03Depuración: cuando algo falla, preguntar la causa antes de pedir la solución.
  • 04Documentación: generar docstrings y revisarlos contra el código real.

Lo que no cambia en ningún paso: cada línea que entra en tu proyecto tiene que poder ser explicada por vos en la defensa o presentación — no solo funcionar.

06

Límites del asistente

Hay momentos en los que usar IA, aunque sea posible, no conviene — porque el objetivo no es resolver el problema lo más rápido posible, sino aprender a resolverlo vos.

Situación¿Conviene usar IA?
Practicar un algoritmo nuevo que se está aprendiendo en clase (por ejemplo, un ordenamiento)No — el objetivo es que el razonamiento quede en tu cabeza, no en el historial de un chat
Una evaluación o examen sin autorización explícita del docenteNo — además de ser una falta, no vas a poder defenderlo después
Depurar un error después de haber intentado entenderlo soloSí — como apoyo, no como primer recurso
Generar una función repetitiva que ya sabés escribir, para ahorrar tiempoSí — no hay aprendizaje nuevo en esa tarea
🚦
La pregunta que conviene hacerse
Antes de abrir el asistente, preguntate: ¿esta tarea es la que tengo que aprender a hacer, o es una tarea que ya sé hacer y solo quiero acelerar? Si es lo primero, resolvela sola o solo primero. La IA va a seguir estando disponible después.
Gatiel dice: "La IA acelera el camino, pero el camino lo tenés que caminar vos. Si te salteás el proceso, no hay atajo que compense lo que no aprendiste."
