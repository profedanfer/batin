Clínica Veterinaria "PataFeliz"

Diseñe e implemente el sistema de registro de atenciones de la clínica: propietarios, mascotas, veterinarios, especialidades y consultas. Practique DDL y DML con una base de datos real que corre directamente en el navegador — no necesita instalar nada.

Iniciando base de datos…
GATIEL

La Clínica Veterinaria "PataFeliz" necesita digitalizar el registro de sus atenciones. Todo se lleva en cuadernos, y eso genera problemas: pierden el historial de las mascotas, no saben qué veterinario atiende cada especialidad, y no pueden calcular fácilmente cuánto facturaron en un mes. Te toca a vos, como especialista en bases de datos, diseñar e implementar el sistema.

Reglas del negocio

Leé con atención — de acá se desprenden las relaciones y restricciones que hay que implementar.

  1. Cada propietario puede tener una o varias mascotas registradas. Toda mascota pertenece a un único propietario.
  2. De cada mascota se registra su nombre, especie, raza y fecha de nacimiento.
  3. Cada veterinario puede tener una o varias especialidades (cirugía, dermatología, odontología…), y cada especialidad puede ser ejercida por varios veterinarios.
  4. Una consulta es la atención de una mascota puntual, en una fecha determinada, realizada por un único veterinario.
  5. En cada consulta se registra el motivo, el diagnóstico y el costo.
  6. No pueden existir dos especialidades con el mismo nombre.
  7. El costo de una consulta no puede ser negativo.
  8. Toda mascota debe tener un propietario asociado; no se permiten mascotas "huérfanas".

Modelo normalizado (3FN)

Este es el modelo que ya está implementado en el script SQL (pestaña "Script SQL"). Identificá en cada tabla la clave primaria (PK) y las claves foráneas (FK) antes de resolver los ejercicios — los vas a necesitar todo el tiempo.

Nota pedagógica: fijate que Veterinario_Especialidad tiene ambas columnas como FK, y que su clave primaria es la combinación de las dos (clave primaria compuesta) — así se resuelve una relación muchos a muchos (M:N).
Antes de escribir cualquier SQL: andá a la pestaña Estructura para ver las 6 tablas con sus PK/FK, y a Script SQL para ver el DDL completo con los datos de ejemplo ya cargados. Después pasá a Ejercicios para resolver las consignas de la guía original.

Creación de tablas (DDL)
Propietarios
CREATE TABLE Propietarios (
    id_propietario INTEGER PRIMARY KEY AUTOINCREMENT,
    nombre VARCHAR(30) NOT NULL,
    apellido VARCHAR(30) NOT NULL,
    telefono VARCHAR(20),
    direccion VARCHAR(60)
);
Mascotas
CREATE TABLE Mascotas (
    id_mascota INTEGER PRIMARY KEY AUTOINCREMENT,
    nombre VARCHAR(30) NOT NULL,
    especie VARCHAR(20) NOT NULL,
    raza VARCHAR(30),
    fecha_nacimiento DATE,
    id_propietario INTEGER NOT NULL,
    FOREIGN KEY (id_propietario) REFERENCES Propietarios(id_propietario)
);
Veterinarios
CREATE TABLE Veterinarios (
    id_veterinario INTEGER PRIMARY KEY AUTOINCREMENT,
    nombre VARCHAR(30) NOT NULL,
    apellido VARCHAR(30) NOT NULL,
    matricula VARCHAR(20) NOT NULL UNIQUE
);
Especialidades
CREATE TABLE Especialidades (
    id_especialidad INTEGER PRIMARY KEY AUTOINCREMENT,
    nombre_especialidad VARCHAR(30) NOT NULL UNIQUE
);
Veterinario_Especialidad
CREATE TABLE Veterinario_Especialidad (
    id_veterinario INTEGER NOT NULL,
    id_especialidad INTEGER NOT NULL,
    PRIMARY KEY (id_veterinario, id_especialidad),
    FOREIGN KEY (id_veterinario) REFERENCES Veterinarios(id_veterinario),
    FOREIGN KEY (id_especialidad) REFERENCES Especialidades(id_especialidad)
);
Consultas
CREATE TABLE Consultas (
    id_consulta INTEGER PRIMARY KEY AUTOINCREMENT,
    fecha DATE NOT NULL,
    motivo VARCHAR(100) NOT NULL,
    diagnostico VARCHAR(150),
    costo DECIMAL(10,2) NOT NULL CHECK (costo >= 0),
    id_mascota INTEGER NOT NULL,
    id_veterinario INTEGER NOT NULL,
    FOREIGN KEY (id_mascota) REFERENCES Mascotas(id_mascota),
    FOREIGN KEY (id_veterinario) REFERENCES Veterinarios(id_veterinario)
);

Soluciones

Compará tus respuestas después de intentarlo en la pestaña Ejercicios — no antes.

Consigna 1 — Mascotas de un propietario
JOIN entre Mascotas y Propietarios, filtrando por el propietario elegido.
SELECT M.nombre, M.especie
FROM Mascotas M
JOIN Propietarios P ON M.id_propietario = P.id_propietario
WHERE P.id_propietario = 1;
Consigna 2 — Historial de consultas de una mascota
Filtro directo sobre Consultas por id_mascota, ordenado por fecha.
SELECT fecha, motivo, diagnostico, costo
FROM Consultas
WHERE id_mascota = 1
ORDER BY fecha;
Consigna 3 — Veterinario y sus especialidades
GROUP_CONCAT agrupa todas las especialidades de un mismo veterinario en una sola fila.
SELECT V.nombre || ' ' || V.apellido AS veterinario,
       GROUP_CONCAT(E.nombre_especialidad, ', ') AS especialidades
FROM Veterinarios V
JOIN Veterinario_Especialidad VE ON V.id_veterinario = VE.id_veterinario
JOIN Especialidades E ON VE.id_especialidad = E.id_especialidad
GROUP BY V.id_veterinario;
Consigna 4 — Total facturado por veterinario
SUM(costo) agrupado por veterinario.
SELECT V.nombre || ' ' || V.apellido AS veterinario,
       SUM(C.costo) AS total_facturado
FROM Consultas C
JOIN Veterinarios V ON C.id_veterinario = V.id_veterinario
GROUP BY V.id_veterinario;
Consigna 5 — Mascotas sin consultas
LEFT JOIN conserva todas las mascotas aunque no tengan consultas asociadas; IS NULL filtra las que no encontraron ninguna coincidencia.
SELECT M.nombre
FROM Mascotas M
LEFT JOIN Consultas C ON M.id_mascota = C.id_mascota
WHERE C.id_consulta IS NULL;
Consigna 6 — Especialidad con más veterinarios
COUNT + GROUP BY + ORDER BY DESC + LIMIT 1 devuelve la especialidad con más veterinarios asociados.
SELECT E.nombre_especialidad, COUNT(VE.id_veterinario) AS cantidad
FROM Especialidades E
JOIN Veterinario_Especialidad VE ON E.id_especialidad = VE.id_especialidad
GROUP BY E.id_especialidad
ORDER BY cantidad DESC
LIMIT 1;
Consigna 7 — Actualizar teléfono
UPDATE con WHERE por clave primaria, para no modificar otras filas por error.
UPDATE Propietarios
SET telefono = '0984-999888'
WHERE id_propietario = 2;
Consigna 8 — Eliminar una consulta
DELETE con WHERE por clave primaria. Consultas no tiene tablas que dependan de ella, así que se elimina sin problemas.
DELETE FROM Consultas
WHERE id_consulta = 4;
Consigna 9 — Integridad referencial
SQLite rechaza el DELETE con un error de tipo "FOREIGN KEY constraint failed". Esto pasa porque María González (id_propietario = 1) tiene mascotas registradas (Rocky y Michi) que la referencian mediante Mascotas.id_propietario. Si se permitiera eliminarla, esas mascotas quedarían "huérfanas" — con una referencia a un propietario que ya no existe, violando la regla de negocio N.° 8. Ese es exactamente el propósito de la integridad referencial: evitar datos inconsistentes. Para eliminar al propietario habría que primero decidir qué hacer con sus mascotas (reasignarlas o eliminarlas también, según la regla del negocio).
Punto de reflexión — Veterinario_Especialidad
Si la especialidad fuera una columna directa en Veterinarios, un veterinario con dos especialidades (como Andrés, que hace Cirugía y Odontología) necesitaría repetir toda su fila dos veces — una por cada especialidad — duplicando nombre, apellido y matrícula. Eso viola la Segunda Forma Normal (2FN) y genera redundancia: si cambia la matrícula de Andrés, habría que actualizarla en varias filas, con riesgo de que queden inconsistentes entre sí. La tabla asociativa Veterinario_Especialidad resuelve esto: cada veterinario aparece una sola vez en Veterinarios, y sus especialidades se registran como filas separadas en la tabla intermedia, sin duplicar ningún otro dato.
